Built from years of ecommerce engineering

These are not weekend experiments. The depth shows up in the workflows that already exist, not in the adjectives.

  • OrdersPayment state and fulfillment state tracked separately, because they are separate facts.
  • InventoryStock held per location, so a multi-warehouse store does not fake it with one number.
  • PaymentsNine provider modules. Money is integer minor units, never a float.
  • FulfillmentEleven carrier modules, plus zones and rates the engine owns.
  • PricingCustomer groups, price lists and quantity breaks under one resolution rule.
  • OperationsRefunds and returns as order states, and an importer that moves no stock.

Questions

What is GoCommerce?

GoCommerce is an open-source, headless ecommerce backend built with Go and PostgreSQL, with a Svelte-based admin compiled into the same binary. It serves 342 documented operations over REST.

What is Svelte Commerce?

Svelte Commerce is an open-source headless ecommerce storefront built with Svelte and SvelteKit. It reaches a commerce backend through a connector package, and 26 connectors exist today.

Is KitCommerce a product?

No. kitcommerce.store is the website presenting GoCommerce and Svelte Commerce. They are independent projects, and there is nothing called KitCommerce to install.

Can I self-host them, and is there a platform fee?

Yes to self-hosting, and no platform fee. Both projects are MIT licensed and designed to run on your own infrastructure. No fee is charged for running the software. Your own servers, domains and third-party services still cost money — the software is free, hosting is not.

Can I use GoCommerce without Svelte Commerce, or the other way round?

Both. GoCommerce serves any client that speaks HTTP, so any storefront framework can drive it. Svelte Commerce runs against 26 commerce backends including Medusa, Vendure, Shopify, Saleor and WooCommerce. Neither requires the other.

Can they work together today?

Not with an installable package. The direct connector between them is in development and unpublished, so pairing them currently means writing that client yourself against the documented GoCommerce API.

How quickly can I get started?

One Docker Compose command. Download docker-compose.yml and env.example from this site, set your secrets in .env, then run docker compose up -d. The first run compiles GoCommerce from source because no image is published yet; later runs are cached.

What does Docker Compose actually start?

Three services: PostgreSQL, GoCommerce — which serves both the commerce API and the admin, because the admin is compiled into the binary — and Caddy as a reverse proxy on port 80. It does not start Svelte Commerce, because the connector that would let the storefront read from GoCommerce is unpublished, and a storefront that cannot load a product is worse than no storefront.

Can I use my own PostgreSQL database?

Yes. GoCommerce takes a DATABASE_URL, so pointing it at a Postgres you already run means setting that variable and removing the bundled postgres service from the compose file.

Is it production ready?

They differ, and it matters. Svelte Commerce has been public for years and runs production stores — arialshop.com is one. GoCommerce reached 1.0, so its API and HTTP contract are stable and breaking either takes a major version. It carries 1,036 tests and a documented contract for every route. No store we know of is running it in production yet — 1.0 is a promise about compatibility, not a record of mileage. Treat it as something to build on deliberately rather than migrate a live business to this week.

Does it work with coding agents?

The repository is written for it: AGENTS.md holds 18 architectural rules, skills/ holds 16 task guides, there is one production dependency so the graph an agent must understand is small, and 1,036 tests catch a wrong edit. The MCP module also lets an agent operate a running store through the same domain services a REST call uses.

Is there a live demo I can click around?

Not yet. A GoCommerce instance is deployed at admin.kitcommerce.store, but every endpoint requires authentication and there is no guest account, so the link opens a sign-in screen. The screenshots on this site are the honest preview until a read-only demo account exists.
