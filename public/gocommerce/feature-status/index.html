Business accounts and ordering

FeatureStatusWhat it doesIn the store’s adminFor buyers
Company accounts Available Each business customer is set up as a company, with its tax number and notes. A company can be active, on hold (it still buys, but pays up front) or closed. Everyone who buys for a company gets that company’s prices. List and search companies; create, edit and delete them Through the API only, no screens yet
Buyer roles Available Each person buying for a company has a role. Admins manage the team and approve orders. Approvers order without waiting and approve other people’s orders. Buyers place orders, and larger ones wait for approval. People join by an emailed invitation, and a company’s admins can manage their own team. Add or invite buyers, change their role, remove them Through the API only, no screens yet
Approval workflows Available Each company sets an amount. A buyer’s order above it waits for an approver instead of going through. The approver approves it, and the order is placed at the prices the buyer saw, or rejects it with a reason. The buyer can also withdraw it. See the requests that are waiting; the company’s own approvers decide Through the API only, no screens yet
Purchase orders Available Each business order can carry the buyer’s purchase order (PO) number, and a company can make it required. Orders can be looked up by that number. PO numbers shown on orders and in receivables, and searchable Through the API only, no screens yet
Requests for quote Available A buyer asks for a price on a list of products. The store sets a price for each line, adds a note and an end date, and sends it. The buyer accepts it, which places the order at those prices, or declines it. List of quotes; price, send or decline each one Through the API only, no screens yet
Credit limits and payment terms Available Each company gets a credit limit and payment terms, such as 30 days. Its buyers order now and pay later, up to the limit. An order that would go over the limit is stopped before it is placed, even when two people order at the same moment. Set the limit and terms; see what each company owes and what is overdue; mark orders paid, one or several at a time Applied automatically when they order
Partial checkout Available A buyer can order some of the items in their basket and leave the rest for later. The same limits and approvals apply. Not needed Svelte Commerce has tick boxes for this, but its GoCommerce connector cannot place an order from Svelte Commerce’s checkout yet.
Repeat orders Available Puts a past order’s items back in the basket at today’s prices, and says which items can no longer be bought. Not needed Svelte Commerce has a “Buy again” page. Its GoCommerce connector does not support signed-in customers yet, so the page cannot show past orders from GoCommerce.

Creating stores Available One request creates a complete new store with its first owner and its web address. Stores can also be paused, restarted, renamed and deleted. A store has to be paused before it can be deleted. List of stores, create a store, a page for each store

Distributors and dealers

FeatureStatusWhat it doesIn the store’s adminFor distributors and dealers
Distributor portal Not built There is no portal website for distributors yet. Everything their staff would do there already works through the API: see their account and terms, manage their team, order and reorder, request quotes, approve orders and follow up leads. — None yet
Bulk ordering Available Add many products at once by product code, up to 500 lines. Any line that can’t be added, such as an unknown code or not enough stock, is listed with the reason, and the rest are added. Uploading a file is not supported yet. Not needed Through the API only, no screens yet
Quotation workflows Available A quote moves from requested, to sent, to accepted, declined or expired. The store can change a quote and send it again, and the buyer is emailed when a quote is ready. Quotes filtered by stage, and a page for each quote Through the API only, no screens yet
Dealer territories Available Each dealer covers areas by country, state or postcode, and each area belongs to one dealer. A state can be written in full or as a short code: “California” and “CA” both work. Set each dealer’s areas; see every dealer’s areas in one list —
Lead routing Available When a customer fills in the “find a dealer” form, the enquiry goes to the dealer that covers their area, and that dealer is emailed. A closed dealer is skipped for the next one, and if no dealer covers the area the store keeps the enquiry. The form doesn’t reveal which dealer it went to, and it limits repeated submissions. See every lead; search and filter them, change their status, or move one to another dealer Dealers see and update their own leads through the API

Instructions

Turning it on

# one store, with B2B (implies -identity)
gocommerce -db "$DATABASE_URL" -admin-token "$TOKEN" -b2b serve

# many stores from one process and one database
gocommerce -db "$DATABASE_URL" \
  -base-domain shops.example.com \
  -platform-token "$GOCOMMERCE_PLATFORM_TOKEN" \
  -b2b platform

Guides in the repository: skills/b2b.md, and "Running many stores" in skills/infrastructure.md. The reasons behind each choice are decisions D66 to D73 in PLAN.md.
