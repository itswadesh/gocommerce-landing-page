Which backends Svelte Commerce speaks to, and how completely

Svelte Commerce talks to a backend through a connector: a package that maps one platform’s API onto a shared 43-service surface. Nothing in the storefront imports a connector by name, so installing a different package runs the same storefront on a different backend.

  • 26 connectors
  • 43 services in the surface
  • 2 at 39/43
  • 0 hand-asserted numbers

Coverage, measured

Coverage is not claimed, it is traced: a script follows each connector’s own request helpers and counts a service as wired only if it genuinely reaches the HTTP layer. Sort order is coverage, highest first.

  • ●Wired — issues a real request
  • ✕No endpoint on the platform — throws rather than faking a session
  • ○Not yet wired

How to read it

A low score is often correct

OpenCart core ships exactly ten API controllers and no product, category or search controller at all. Its 9/43 is the honest ceiling for that API, not a to-do list.

“No endpoint” is not a gap

Where a platform has no real customer-auth endpoint, auth throws rather than minting a session. A stub that logs anyone in for any password is an auth bypass, not a placeholder.

Some services count for nobody

Reels, deals, chat, gallery, popularity and a few others are Litekart-native concepts with no equivalent elsewhere. They stay documented placeholders and are excluded from the gaps column.

The one caveat that matters

Read this before choosing

Every connector was written by reading its platform’s authoritative source — the OpenAPI spec, the RAML, the router registration, or the controller source. No endpoint was guessed, and where a route could not be verified it was left an explicit placeholder rather than shipped as a plausible path that 404s in a merchant’s store.

But reading a spec is not running against a real store. None of these connectors has been exercised against a live production instance of its platform. That is the single biggest gap in this table, and it is the thing platform maintainers can help with that we cannot do alone.

Questions about backends

How many backends does Svelte Commerce support?

26 connectors exist today, covering Litekart, Vendure, Medusa, Broadleaf, Saleor, Shopware, Virto Commerce, WooCommerce, Magento, Spree, X-Cart, EverShop, Spryker, nopCommerce, PrestaShop, Sylius, Swell, Bagisto, commercetools, OroCommerce, Sharetribe, CS-Cart, Shuup, Shopify, Django Oscar and OpenCart. They differ a great deal in how complete they are, which is what the coverage column on this page is for.

Which connectors are the most complete?

Litekart and Vendure, both at 39 of 43 services, with cart, checkout and auth all wired. Litekart is the reference implementation and Vendure’s GraphQL Shop API covers essentially the whole surface.

Is the coverage number reliable?

It is measured rather than asserted. A script traces which service methods transitively reach the HTTP layer, following each connector’s own request helpers, and a service counts as wired only if it genuinely issues a request or delegates to one that does. What the number does not tell you is whether the connector has been run against a live store, because none of them has.

Can I use Svelte Commerce with GoCommerce?

Not yet. The GoCommerce connector is in development and unpublished, which is why it appears at the bottom of this table with no coverage. GoCommerce serves a documented JSON API that any client can call, so pairing them today means writing that client yourself.

What if my platform is not listed?

Then there is no adapter for it yet. A connector is a TypeScript package mapping one platform’s API onto the shared service surface, so adding one does not require changing the storefront. The existing 26 are the pattern to follow.

Pick a backend, or help fix one

The storefront is the same either way. The connector is what changes.
