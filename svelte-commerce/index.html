Svelte Commerce — a modern open-source ecommerce storefront

Svelte Commerce provides a fast, customizable storefront for headless ecommerce, built around the Svelte ecosystem. It is a standalone project that connects to GoCommerce or another compatible commerce backend.

A store running on it today

Not a mockup and not a demo theme — a production jewellery store built on Svelte Commerce, captured on 21 September 2026.

What the storefront gives you

The customer-facing half of a store: the pages people actually shop on, built as Svelte components you own and can restyle.

SvelteKit

Server-side rendering and client-side navigation from one framework, so the first paint is HTML and the second page is instant.

Headless

The storefront holds no commerce rules of its own. Prices, stock and orders come from the backend, which means the same storefront works over several of them.

Customizable UI

Ordinary Svelte components, not a theme DSL. Change a template by editing the template.

SEO-friendly rendering

Product and category pages are rendered on the server, so a crawler sees the catalogue rather than an empty shell waiting for JavaScript.

Backend-independent

Six commerce backends are supported today. Switching one out is a data-layer change, not a rewrite of the storefront.

Yours under MIT

Fork it, rebrand it, ship it for a client. There is no licence tier and nothing phones home.

Backends it speaks to today

Svelte Commerce is a headless storefront capable of integrating with compatible commerce backends. These six are supported now.

  • Medusa
  • Shopify
  • Saleor
  • Vendure
  • WooCommerce
  • Litekart

That list is the current state of the repository, not a roadmap. If a backend is not on it, there is no adapter for it yet.

Using it with GoCommerce

GoCommerce ↔ Svelte Commerce

Connector in development

GoCommerce is not yet one of the backends above. The connector that maps the GoCommerce API onto the Svelte Commerce data layer is being written and is not published.

Until it lands, pairing the two means writing that client yourself against the documented GoCommerce API — 342 operations, published as OpenAPI. That is the honest state of it, and it is the single most useful thing anybody could help with.

Run the storefront locally

You need Node.js and a commerce backend to point it at. The storefront holds no data of its own, so it needs something to read from before it shows a catalogue.

Clone it, install, point it at a backend

# 1 — get the source
git clone https://github.com/itswadesh/svelte-commerce
cd svelte-commerce

# 2 — install dependencies
pnpm install

# 3 — tell it which backend to read from
cp .env.example .env
#    then edit .env for your backend and its endpoint

# 4 — run it
pnpm dev

The repository’s own README is the authority on environment variables for each backend, because those change with the adapters. Read the setup docs.

Questions people actually ask

Direct answers, including the unflattering ones. If a question here has a bad answer, that is the answer.

Which commerce backends does Svelte Commerce support?

Medusa, Shopify, Saleor, Vendure, WooCommerce and Litekart. That is the current state of the repository rather than a roadmap: if a backend is not on that list, there is no adapter for it yet.

Can I use Svelte Commerce with GoCommerce today?

Not without writing the glue yourself. The connector that maps the GoCommerce API onto the Svelte Commerce data layer is in development and unpublished. GoCommerce serves a documented JSON API that any framework can call, so it is possible, but you would be writing that client.

Does Svelte Commerce need GoCommerce?

No. Svelte Commerce is a standalone storefront and predates GoCommerce by years. It runs against any of the six backends it supports today, and GoCommerce is not one of them yet.

Is it production-ready?

It has been public for years and runs production stores — arialshop.com is one of them, and it is linked on this page so you can judge it yourself rather than take our word for it.

Can I change the design?

Yes. The storefront is ordinary Svelte components rather than a theme DSL, so changing a template means editing that template. It is MIT licensed, so you can rebrand it and ship it for a client.

Is it good for SEO?

Product and category pages are server-rendered by SvelteKit, so a crawler receives HTML with the catalogue in it rather than an empty shell. The rest of a store’s SEO — titles, structured data, canonical URLs — is yours to write, as it is in any storefront.

Is there a paid tier?

No. It is MIT source you run yourself. There is no hosted offering, no paid tier and nothing to buy.
